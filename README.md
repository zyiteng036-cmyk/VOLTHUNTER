## 💻 プロジェクト概要

* **ゲーム概要:** 攻撃をジャストでかわし、強力な反撃へつなげる3Dアクションゲーム
* **コンセプト:** 最大のピンチを最高のリターンにしろ！
* **開発環境:** Unreal Engine 5.5.4 / Visual Studio 2022 / C++
* **制作期間:** 2025年11月中旬～2026年3月上旬（約4か月）
* **チーム人数:** 4人（プログラマー2人、プランナー1人、デザイナー1人）

### 担当箇所

* **プログラム**
  * プレイヤー操作全般
  * 攻撃・コンボシステム
  * ジャスト回避・カウンター攻撃
  * Gameplay Ability Systemを利用したアクション制御
  * カメラシステム全般
  * 設定画面
  * Splineを利用した床配置・電気移動
  * ボスの追尾ビーム攻撃
  * リスポーン機能

* **デザイン・アート**
  * Niagaraを利用したエフェクト制作
  * 設定画面UI
  * 床・リスポーン地点のStaticMesh制作

## 💡 技術的なこだわり・アピールポイント

本作では、アクションゲームとしての**直感的な操作感と入力レスポンス**を重視しました。

同時に、機能追加や調整によって既存処理が複雑化しないよう、Gameplay Ability System、GameplayTag、コンポーネント分割、データ駆動設計を組み合わせています。

---

### 1. Gameplay Ability Systemを利用したアクション制御

Unreal EngineのGameplay Ability System（GAS）を利用し、攻撃・回避・ダッシュ・ジャンプ・スキルなどを、それぞれ独立したGameplayAbilityとして実装しました。

GASは、キャラクターのアクションや状態、発動条件、キャンセル条件などを管理するためのUnreal Engine標準システムです。

本作では、PlayerCharacterにすべての処理を集中させず、入力受付、Ability、各Componentへ役割を分割しています。

```text
Enhanced Input
        ↓
PlayerCharacter
入力をGASへ通知
        ↓
AbilitySystemComponent
Abilityの起動・入力状態の管理
        ↓
GameplayAbility
攻撃・回避・ダッシュ・スキル
        ↓
各Component
実際の移動・攻撃・カメラ処理
```

#### GameplayTagによる状態管理

攻撃中、回避中、最大溜め状態などをGameplayTagで表現しています。

```text
State.Attack.HeavyCharging
State.Attack.HeavyCharged
State.Locomotion.Dodging
State.Locomotion.Dashing
```

複数のboolを相互参照する構造を避け、Abilityの発動条件や競合状態を共通の形式で判定できるようにしました。

#### 結果

* アクションごとの処理を独立
* Ability単位で機能を追加可能
* アクション同士の競合を抑制
* PlayerCharacterの肥大化を防止
* 状態の解除漏れや管理ミスを削減

---

### 2. GameplayTagとComboTableによるデータ駆動型コンボ

攻撃入力をGameplayTagとして管理し、現在の攻撃・入力・プレイヤーの状態から、次に発動するGameplayAbilityを決定しています。

#### ComboTableとは

ComboTableは、

> どの攻撃中に、どの入力と状態を満たしたら、次にどの攻撃を発動するか

をUnreal Engineのエディタ上で設定するために作成した、独自のデータアセットです。

ComboTableの1つのセルが、1つの攻撃派生ルールになっています。

```text
現在の攻撃Tag
        ＋
入力Tag
        ＋
必要な状態Tag
        ＋
禁止する状態Tag
        ↓
次に発動するGameplayAbility
```

主な設定項目は以下の通りです。

| 項目 | 内容 |
| :--- | :--- |
| `CurrentAttackTag` | 派生元となる現在の攻撃 |
| `InputTag` | 派生に使用する入力 |
| `RequiredTags` | 派生に必要な状態 |
| `BlockedTags` | 所持していると派生できない状態 |
| `NextAbilityClass` | 次に発動する攻撃Ability |
| `CancelAbilityTags` | 遷移時に終了するAbility |
| `bCancelCurrentAttack` | 現在の攻撃を終了して遷移するか |

#### 強攻撃のShort / Full分岐

強攻撃では、ボタンを離した際に共通の入力Tagを送信します。

```text
Input.Attack.Heavy.Release
```

最大溜め状態を表すTagの有無をComboTableで判定し、Short攻撃またはFull攻撃へ派生させています。

```text
State.Attack.HeavyChargedあり
        ↓
Heavy Full

State.Attack.HeavyChargedなし
        ↓
Heavy Short
```

攻撃の接続条件をC++内のif文ではなくデータへ分離することで、コードを書き換えずにコンボ順や派生条件を調整できます。

#### 結果

* コンボの接続順をエディタ上で変更可能
* セルの追加によって攻撃派生を拡張
* GameplayTagによる状態別の分岐
* 同じ入力から複数の攻撃へ派生
* コンボ追加時のC++変更を削減

### 3. 2段階式先行入力バッファ

攻撃アニメーション内に、入力を保存する「予約受付区間」と、次の攻撃へ切り替える「発動受付区間」を設けています。

```text
攻撃アニメーション

予約受付区間
├──────────────┤
     入力を保存

          発動受付区間
          ├──────────┤
          予約済みなら即発動
```

少し早く入力された場合でも、その入力を一度保存し、発動可能なタイミングへ到達した瞬間に次のGameplayAbilityを起動します。

予約と発動を分けることで、攻撃モーションの見た目を維持しながら、プレイヤーごとの入力リズムを吸収しています。

#### 結果

* 先行入力を取りこぼさない
* 過度に正確な入力タイミングを要求しない
* モーションを崩さずコンボを接続
* 滑らかで反応の良い操作感を実現

### 4. ジャスト回避後の攻撃入力予約

ジャスト回避成功後は、スロー演出や敵を注視するカメラ演出が入るため、入力した瞬間に攻撃を発動できない時間があります。

その間も攻撃入力を保存し、発動可能になった瞬間にカウンター攻撃へつなげています。

```text
ジャスト回避成功
        ↓
攻撃入力を保存
        ↓
スロー・敵注視カメラ
        ↓
カウンター発動可能
        ↓
保存した攻撃Abilityを発動
```

強攻撃では、押下入力と離し入力を別々に保存します。

予約中にボタンを離した場合でも強攻撃の予約を維持し、離し状態に応じた攻撃へ派生できるようにしました。

#### 結果

* 演出中の攻撃入力を取りこぼさない
* ジャスト回避から反撃へ滑らかに接続
* 弱攻撃・強攻撃の両方に対応
* スロー演出と入力レスポンスを両立

### 5. カメラレイヤーパイプライン

カメラ距離、回転、FOV、SocketOffsetなどの情報を`FCameraContext`へまとめ、複数のカメラレイヤーが順番に値を補正するパイプラインを構築しました。

各レイヤーは、1クラスにつき1つのカメラ機能を担当します。

```text
CameraRigComponent
        ↓
FCameraContext
共通のカメラ情報
        ↓
BossBattle
        ↓
Lead
        ↓
LookDown
        ↓
Action
        ↓
SoftClamp
        ↓
Opening / Die / Clear
        ↓
SpringArm・Cameraへ最終値を反映
```

#### 主なカメラレイヤー

| レイヤー | 内容 |
| :--- | :--- |
| `BossBattle` | ボスとの距離に応じてカメラ距離とFOVを変更 |
| `Lead` | 移動方向・速度・視点回転に応じた先読み |
| `LookDown` | 落下中に着地点を確認しやすくする見下ろし |
| `Action` | スキル・ジャスト回避・Spline移動時の演出 |
| `SoftClamp` | プレイヤーが画面外へ出すぎないよう補正 |
| `OpeningCamera` | ゲーム開始時の専用カメラ |
| `DieCamera` | プレイヤー死亡時の専用カメラ |
| `ClearCamera` | ゲームクリア時の専用カメラ |

新しいカメラ機能を追加する際も、既存レイヤーの処理を変更せず、新しいレイヤークラスの追加とパイプラインへの登録によって拡張できます。

#### 結果

* カメラ処理の適用順を明確化
* レイヤー単位で有効・無効を切り替え可能
* 既存のカメラ処理へ与える影響を削減
* 問題が発生したレイヤーを特定しやすい
* 状況別カメラを追加しやすい構成

### 6. 状況に応じたカメラ制御

#### 移動先読みカメラ

プレイヤーの移動方向・速度・視点回転から先読み量を計算し、進行方向の視野を広げます。

移動を停止した後は急に中央へ戻さず、滑らかに通常構図へ復帰させています。

#### 画面外防止カメラ

プレイヤーが画面内のデッドゾーンを超えた場合、超過量を計算してカメラを平行移動させます。

カメラを急激に中央へ戻さず、プレイヤーを滑らかに画面内へ収めています。

#### ボス戦カメラ

プレイヤーとボスの水平距離に応じて、カメラ距離とFOVを動的に変更します。

近距離では迫力を維持し、遠距離ではカメラを引いて両者を確認しやすくしています。

#### ジャスト回避後の敵注視

回避操作時はカメラ入力から指が離れやすいため、ジャスト回避成功後に敵方向へカメラを自動補正します。

現在のPitchを維持しながらYawだけを補間し、視点を大きく崩さずカウンター攻撃へつなげやすくしました。

#### スキル・Spline移動カメラ

スキル発動時は、一度プレイヤーへ寄った後に大きくカメラを引く2段階の演出を行います。

Spline移動中は、カメラ距離・FOV・SocketOffsetを同時に補間し、高速移動用の構図へ切り替えます。

どちらも終了後は通常カメラへ滑らかに復帰します。

#### オープニング・死亡・クリアカメラ

ゲーム開始、プレイヤー死亡、ゲームクリア時には、通常カメラとは異なる専用カメラ演出を適用します。

クリア時は他のカメラレイヤーを停止し、クリアカメラだけを実行することで、背面・側面・正面の順に構図を切り替えています。

### 7. 設定画面

プレイヤーの操作環境に合わせられるよう、設定画面を実装しました。

* カメラ感度
* カメラ横入力反転
* カメラ縦入力反転
* 画面の明るさ

設定した値は、プレイヤーのカメラ入力や画面表示へ反映されます。

## 🚀 インストールと実行方法

※ 本作の実行には Windows 環境が必要です。

1. GitHubの **[Releases]** ページから `Windows Build v1.0` (zipファイル) をダウンロードします。
2. ダウンロードした zip ファイルを任意のフォルダに展開します。
3. 展開したフォルダ内にある実行ファイル（`.exe`）を起動するとゲームが開始されます。
